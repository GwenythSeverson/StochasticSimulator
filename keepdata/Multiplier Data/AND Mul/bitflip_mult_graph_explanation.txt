================================================================================
STOCHASTIC COMPUTING MULTIPLIER EXHAUSTIVE FAULT ANALYSIS: GRAPH GUIDE
================================================================================
This document provides a comprehensive guide to interpreting the 8-graph fault-
injection analysis suite generated by "analyze_multiplier_faults2.m". It is
written to explain the data pool, mathematical equations, and visual behaviors 
clearly to anyone reviewing these results.

--------------------------------------------------------------------------------
1. THE CORE DATA POOL
--------------------------------------------------------------------------------
All charts are plotted using the database "32bit_exhaustive_multiplier_trials.csv".
This file contains exactly 163,840 rows, representing an exhaustive simulation 
of every possible fractional representation pair in a 32-bit system:
  * Count A (Stream A ones count): Swept from 0 to 31 (32 values)
  * Count B (Stream B ones count): Swept from 0 to 31 (32 values)
  * Organizations: 5 distinct random shufflings of the bitstream per pair
  * Bits Flipped: 32 levels of fault intensity (1 to 32 bit flips in Stream A)
  * Total Trials = 32 (A values) * 32 (B values) * 5 (orgs) * 32 (flips) = 163,840

--------------------------------------------------------------------------------
2. CORE ERROR EQUATIONS
--------------------------------------------------------------------------------
We evaluate accuracy by comparing the simulated hardware output with the ideal 
continuous mathematical product. All values below represent ones counts (0 to 31):

* Ideal Product (Unquantized):
  IdealVal = (CountA * CountB) / 32.0

* Expected Clean Output (Quantized ZCE):
  ExpectedCleanOnes = round((CountA * CountB) / 32.0)

* Simulated Faulted Output:
  FaultedOnesCount (The ones count of the output after Stream A is faulted)

* Total Error (Precision Limit + Bit Flip Faults):
  TotalError = FaultedOnesCount - IdealVal

* Precision Error (Quantization/Rounding limit):
  PrecisionError = ExpectedCleanOnes - IdealVal

* Bit Flip Error (Pure fault damage):
  BitFlipError = FaultedOnesCount - ExpectedCleanOnes

Note: TotalError = PrecisionError + BitFlipError (this holds exactly).

--------------------------------------------------------------------------------
3. GRAPH-BY-GRAPH BREAKDOWN
--------------------------------------------------------------------------------

--------------------------------------------------------------------------------
GRAPH 1: TOTAL ERROR SCALING & DEGRADATION
--------------------------------------------------------------------------------
* X-Axis: Number of Bits Flipped (1 to 32)
* Y-Axis: Mean Absolute Total Error
* Y-Axis Equation:
  Y = mean( abs( TotalError ) ) grouped by BitsFlipped
* Data Pool: All 163,840 trials, grouped into 32 bins (one per flip level).
* Why it looks the way it does:
  As the number of bit flips increases, the error size climbs steadily and then 
  levels off. When 1 or 2 bits are flipped, the system stays close to its target. 
  By the time 32 bits are flipped, Stream A is completely randomized, meaning the 
  multiplier is essentially guessing, producing a high average error. The vertical
  error bars show the standard deviation (uncertainty) which grows with fault intensity.

--------------------------------------------------------------------------------
GRAPH 2: FAULT SIGN BIAS
--------------------------------------------------------------------------------
* X-Axis: Count A (Input Stream A ones count, 0 to 31)
* Y-Axis: Mean Raw Total Error
* Y-Axis Equation:
  Y = mean( TotalError ) grouped by CountA
* Data Pool: All 163,840 trials, grouped into 32 bins (one per CountA value).
* Why it looks the way it does:
  This graph shows a straight downward-sloping diagonal crossing zero at Count A = 16.
  * When Count A is low (mostly 0s), noise flips 0s to 1s, pulling the output density 
    upward (positive raw error).
  * When Count A is high (mostly 1s), noise flips 1s to 0s, pulling the output density 
    downward (negative raw error).
  * At Count A = 16 (equal ones and zeros), upward and downward flips balance out, 
    resulting in zero net bias.
  The line is strictly linear because we only inject faults into Stream A, making the 
  relationship between stream density and flip probability a first-order equation.

--------------------------------------------------------------------------------
GRAPH 3: TOTAL ERROR VARIANCE & BOUNDS
--------------------------------------------------------------------------------
* X-Axis: Selected Levels of Bits Flipped (2, 4, 8, 16, 24, 32)
* Y-Axis: Total Error Distribution Range
* Y-Axis Equation:
  Y = Distribution boxplot of raw TotalError for the selected flip levels.
* Data Pool: Subset of trials matching the selected flip intensities (30,720 trials).
* Why it looks the way it does:
  This box chart shows how the range of mistakes expands. At 2 flips, the box is 
  highly compressed near 0, meaning the error is very predictable. As flips increase,
  the height of the box stretches. This shows that higher fault intensities don't 
  just make the average error larger; they make the output highly volatile and 
  unpredictable (large error variance).

--------------------------------------------------------------------------------
GRAPH 4: EXHAUSTIVE 32X32 RESOLUTION GRID
--------------------------------------------------------------------------------
* X-Axis: Count A (0 to 31)
* Y-Axis: Count B (0 to 31)
* Y-Axis Equation:
  Plots the raw coordinate pair (CountA, CountB) for every simulated trial.
* Data Pool: All 163,840 trials.
* Why it looks the way it does:
  It is a solid, dense 32x32 grid of points. This visually proves that our test is 
  exhaustive: it has no "blind spots" or skipped values. It covers all combinations, 
  including the edge cases (0 and 31 counts) where stochastic math reaches boundary 
  limits.

--------------------------------------------------------------------------------
GRAPH 5: PRECISION VS. BIT FLIP ERROR SCALING
--------------------------------------------------------------------------------
* X-Axis: Number of Bits Flipped (1 to 32)
* Y-Axis: Mean Absolute Error
* Y-Axis Equations:
  Green line: Y = mean( abs( PrecisionError ) ) grouped by BitsFlipped
  Magenta line: Y = mean( abs( BitFlipError ) ) grouped by BitsFlipped
* Data Pool: All 163,840 trials, grouped by the 32 flip levels.
* Why it looks the way it does:
  This graph compares the two independent components of error:
  * The Green line (Precision Error) is flat at ~0.15 ones. This represents the 
    inherent rounding noise of a 32-bit stream. It never changes because rounding 
    limits do not depend on hardware faults.
  * The Magenta line (Bit Flip Error) starts at 0 and rises linearly as more bits 
    are flipped.
  * Crossover Point (8 flips): Below 8 flips, the representation limits of the 32-bit 
    width dominate the output error. Above 8 flips, the hardware faults dominate.

--------------------------------------------------------------------------------
GRAPH 6: RESULTING BITSTREAM FAULT SIGN BIAS
--------------------------------------------------------------------------------
* X-Axis: Expected Clean Output Ones Count (0 to 30)
* Y-Axis: Mean Raw Total Error
* Y-Axis Equation:
  Y = mean( TotalError ) grouped by ExpectedCleanOnes
* Data Pool: All 163,840 trials, grouped into bins based on the clean output ones.
* Why it looks the way it does:
  Like Graph 2, this has a downward diagonal shape, but it represents the output 
  density. 
  * Near 0 output: Since you can't have fewer than 0 ones, faults in A can only cause 
    accidental overlapping ones with B, resulting in a positive bias. This positive 
    bias is slight because a low-density B stream filters out (blocks) most of A's 
    faulty bits.
  * Near 30 output: Both A and B must be 31 (representing the maximum density 31/32). 
    Since B has 31 ones, it acts as an almost fully open gate. Every fault in A turns 
    a one to a zero, propagating directly to the output. This causes a large negative 
    bias.
  * The bumpy "peaks and drops" in the middle occur because of integer arithmetic; 
    different output numbers are composed of different numbers of contributing input 
    pairs, causing minor statistical variation.

--------------------------------------------------------------------------------
GRAPH 7: CLEAN OUTPUT TRIAL DISTRIBUTION
--------------------------------------------------------------------------------
* X-Axis: Expected Clean Output Ones Count (0 to 30)
* Y-Axis: Number of Trials
* Y-Axis Equation:
  Y = Count of trials in the dataset where ExpectedCleanOnes == X
* Data Pool: All 163,840 trials.
* Why it looks the way it does:
  This bar chart has a massive peak at 0 ones (nearly 14,000 trials) and drops off to 
  almost nothing at the highest output ones count 30 (160 trials, which comes only 
  from the single (31, 31) combination). This unevenness explains why the edges of 
  Graph 6 have more noise: they have far fewer samples to average out the statistical 
  noise of the bit flips.

--------------------------------------------------------------------------------
GRAPH 8: INPUT STREAM A TRIAL DISTRIBUTION
--------------------------------------------------------------------------------
* X-Axis: Count A (Input Stream A ones count, 0 to 31)
* Y-Axis: Number of Trials
* Y-Axis Equation:
  Y = Count of trials in the dataset where CountA == X
* Data Pool: All 163,840 trials.
* Why it looks the way it does:
  This bar chart is perfectly flat and uniform at exactly 5,120 trials for every bin. 
  This visually proves that our test database was completely unbiased and balanced 
  during generation; every input density was evaluated equally.
